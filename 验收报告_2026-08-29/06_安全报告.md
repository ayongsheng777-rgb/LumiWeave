# 06 安全报告 — 绵绣 LumiWeave

> Phase 8：安全验收（代码审计 + 线上实测双重验证）｜ 评分维度权重 15%

## 🔴 P0 严重问题（必须立即修复）

### S1. /uploads 路径穿越 → 未授权任意文件读取 → 全系统接管链【已实测复现】
- **位置**：backend/app/main.py:190（`/uploads/{fname:path}` 在免鉴权白名单）
- **实测证据**（全部 HTTP 200，未带任何凭证）：
  - `curl --path-as-is /uploads/../otp_secret` → 返回 32 字节（TOTP 种子 base32）
  - `curl --path-as-is /uploads/../session_secret` → 返回 64 字节（会话签名密钥）
  - `curl --path-as-is /uploads/../../../../etc/passwd` → 200（容器任意文件）
- **影响**：拿到 otp_secret 可自算动态码登录 → 完整接管系统；session_secret 泄露可伪造会话
- **修复**：`p = (d / fname).resolve()` 后校验 `p.is_relative_to(d.resolve())`，拒绝含 `..` 路径

## 🟠 P1 重大问题

### S2. OTP 登录无防爆破【代码确认】
- /api/auth/login 无限流、无失败锁定；6 位 OTP 仅 10⁶ 空间，±1 窗口实际 3×10⁶ 尝试即可覆盖
- 修复：按 IP 限流（5 次/分）+ 连续失败指数退避 + 审计日志

### S3. MCP 权限模型未强制【已实测复现】
- `mcp/auth/permission.py` 定义了 read/write/execute 模型，但 `has_permission()` 全仓库零调用
- **实测**：用 permissions=["read"] 的 token 调写工具 canvas.create，请求直达工具执行层（仅因缺参数报 pydantic 错，而非 403 权限拦截）
- 影响：任何有效 MCP token 可调 workflow.execute / film.video_generate 等，直接消耗云端费用
- 修复：工具分发层统一调用 has_permission，不足返回 403

### S4. PG/Redis 弱口令暴露宿主机【配置确认】
- compose 默认 PG 口令 `lumiweave2026` + 0.0.0.0:5435；Redis 无密码 + 0.0.0.0:6385
- 影响：局域网内可直接连库读写、Redis 投毒
- 修复：端口绑 `127.0.0.1:` 前缀、Redis 加 requirepass、删除 compose 默认口令

### S5. /api/assets/dir 任意目录设置 + 公开 /uploads 联动放大
- 认证后可将素材目录指向任意路径（当前值 `F:\绵绣素材库`），与 S1 联动可读宿主机任意目录
- 修复：assets_dir 限制在 DATA_DIR 子树内

## ⚪ 已通过项（审计确认安全）

- ✅ **SQL 注入**：全部参数化，未发现注入点
- ✅ **XSS**：无 dangerouslySetInnerHTML / rehype-raw，ReactMarkdown 默认安全
- ✅ **文件上传**：扩展名白名单 + 20MB 限制 + UUID 改名（不含 svg）
- ✅ **TOTP 实现**：RFC 6238 合规（SHA1/6位/30s/±1窗口）
- ✅ **SESSION_SECRET**：无硬编码默认，自动生成 64 位 hex 落盘
- ✅ **api_key 脱敏**：mask_key + has_api_key 返回，掩码回传保留原值
- ✅ **subprocess**：全 list 参数无 shell=True
- ✅ **主 API 鉴权**：中间件白名单制，无 token/假 token 均 401（实测）

## 结论

认证体系主干是健康的，但 **S1 是教科书级 P0**——一个免鉴权静态路由把整个认证体系架空。安全是本项目最短板的维度。**安全单项得分：45/100**。修复 S1+S3+S4 后可回升至 75+。
